# Глоссарий saltbox-compose

Здесь собраны термины, которые встречаются на границах компонентов Salt.Box. Названия в скобках связывают язык оператора с именами в конфигурации, API и интерфейсе. Продуктовый глоссарий находится в репозитории `saltbox-docs`, примеры проверки развёртывания — в [AGENTS.md](./AGENTS.md).

## Состав установки

**Инстанс Salt.Box** — отдельное развёртывание платформы со своими настройками, данными и набором подключённых компонентов.

**Система управления Salt.Box** — серверная часть платформы, через которую оператор управляет устройствами. Она включает ядро, хранилище данных и шину обмена сообщениями.

**Дополнительный модуль Salt.Box** — расширение возможностей инстанса, например «Инвентаризация» или «Метрики». Один модуль может включать несколько сервисов.

**Профиль Compose** — именованная группа сервисов, которую можно включить при развёртывании. В базовой конфигурации Salt.Box профили позволяют независимо включать встроенную MongoDB и локальный контроллер.

**Файл переопределений Compose** — дополнительное описание, которое Compose объединяет с базовой конфигурацией. Например, переопределение для разработки позволяет собирать ядро из локальных исходников.

**Сервис Compose** — именованная часть развёртывания с собственной командой запуска и зависимостями. API и фоновые обработчики одного модуля Salt.Box могут быть отдельными сервисами Compose.

**Локальные настройки инстанса** — значения, которые оператор выбирает для конкретной установки, например внешний адрес, подключённые модули и профили. Основной Compose-проект читает их из `override.env`.

## Регистрация сервисов и интерфейс

**Шлюз Salt.Box (Gateway)** — компонент, который принимает API-запросы, проверяет доступ и направляет запросы зарегистрированному сервису. Входной HTTPS-прокси принимает внешние соединения и передаёт запросы шлюзу или соответствующему фронтенду.

**Discovery** — механизм, через который сервисы объявляют шлюзу свои экземпляры, маршруты и параметры интерфейса. Из этих сведений шлюз формирует в том числе конфигурацию для браузера.

**Сервис в Discovery** — логически именованный участник платформы, например `core`. С одним именем сервиса могут быть связаны несколько экземпляров.

**Экземпляр сервиса (Service Instance)** — конкретный адресуемый участник регистрации со своим идентификатором, адресом и состоянием доступности. Один инстанс Salt.Box может включать несколько экземпляров одного сервиса.

**Микрофронтенд Salt.Box** — самостоятельно поставляемая часть веб-интерфейса, которую загружает оболочка. Микрофронтенд может предоставить экран, пункт настроек или действие на экране другого модуля.

**Плагин интерфейса** — расширение в согласованном месте существующего экрана, например действие над устройством в карточке миньона. Его может предоставить микрофронтенд подключённого модуля.

**Политика доступа** — правило, определяющее, какие операции над какими ресурсами разрешены пользователю. Для описания желаемой конфигурации устройств в спецификации используй термин «состояние» или название соответствующей задачи.

## Управление устройствами

**Контроллер Salt.Box (Salt Master с Bridge)** — компонент, через который система управления передаёт команды агентам и получает результаты. Локальный контроллер развёртывается в составе инстанса, внешний подключается отдельно.

**Агент Salt.Box (Salt Minion)** — компонент на управляемом устройстве, который выполняет команды контроллера и возвращает результаты.

**Ядро Salt.Box (Core)** — сервис системы управления, который хранит задачи, инициирует выполнение команд Salt и собирает результаты.

**Salt.Box Bridge** — расширение Salt Master для обмена командами и событиями с ядром Salt.Box.

**Коллекция** — именованная группа управляемых устройств. Коллекцию можно использовать для выбора устройств, на которые распространяется задача.

**Цель Salt (Target)** — указание, к каким миньонам относится конкретная операция на контроллере. Цель может обозначать одно устройство или множество устройств.

**Задача (Task)** — описание операций, целей и условий выполнения в Salt.Box. Одна задача может приводить к нескольким вызовам Salt.

**Команда (Job)** — отдельный вызов Salt на контроллере, для которого можно проследить ход выполнения и получить результаты по устройствам.

**Идентификатор команды (JID)** — идентификатор запуска команды Salt. По нему можно связать запуск с ответами от нескольких миньонов.

**Результат команды (Job Return)** — ответ отдельного миньона на команду. Для команды с несколькими целевыми устройствами результаты могут поступить в разное время.

**Шаблон задачи (Task Template)** — переиспользуемое описание операций и их параметров, на основе которого создают задачи.

**Configuration Box** — SLS-репозиторий с описаниями конфигураций и манифестом Salt.Box. Его содержимое синхронизируется с подключёнными контроллерами.

**AUX-файл** — дополнительный файл, указанный в манифесте Configuration Box для доставки вместе с конфигурацией. Например, это может быть установочный пакет для управляемых устройств.

## Данные и операции дополнительных модулей

**Дополнительные данные устройства (Extra Data)** — сведения о миньоне, объединённые в категории. «Инвентаризация» может заполнить их по результатам сбора данных об оборудовании и программах.

**Категория дополнительных данных** — описание набора полей для однотипных сведений об устройствах. Категория задаёт структуру, а записи конкретного устройства содержат значения.

**Задача планировщика** — описание того, какую операцию сервиса нужно запускать по заданному расписанию. У одного расписания может быть несколько запусков со своими результатами.

**Сценарий (Migration)** — последовательность шагов, ход выполнения которой оператор отслеживает в модуле «Сценарии». Миграция данных при обновлении сервиса означает преобразование хранимых данных между версиями.

**Попытка шага сценария** — одно выполнение шага. При повторе у того же шага появляется новая попытка, а для шага с командой Salt можно проследить JID и результат конкретной попытки.

**Событие аудита** — запись о действии над ресурсом Salt.Box, которую принимает модуль «Аудит». По таким записям можно проследить историю действий.

**Метрика Salt.Box** — числовой показатель работы системы, например счётчик запущенных команд. Модуль «Метрики» предоставляет показатели для мониторинга.

**Аналитическая витрина** — данные Salt.Box, подготовленные для отчётов и дашбордов. Например, сведения об устройствах и их коллекциях попадают в витрину после синхронизации.

**Источник файлов** — именованная область хранилища, доступная через файловый менеджер с заданными правами. У одной установки могут быть отдельные источники для пользовательских состояний, Configuration Boxes и файлов сценариев.
